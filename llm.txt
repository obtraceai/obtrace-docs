Obtrace — AI-native observability, incident detection, and auto-remediation platform.

Obtrace is a hosted SaaS (like Datadog or Sentry). Users are customers integrating
Obtrace into their apps. Integration = install SDK + set env vars. The SDK is
self-contained — do NOT create wrappers, providers, hooks, or config modules.

Docs: https://docs.obtrace.ai/docs
Dashboard: https://app.obtrace.ai
Quickstart: https://docs.obtrace.ai/docs/quickstart

BACKEND SDKs
-------------

Node.js / Bun (@obtrace/sdk):
  npm install @obtrace/sdk

  import { initNodeSDK } from '@obtrace/sdk/node'  // must be first import
  initNodeSDK({ apiKey: '...', serviceName: 'my-api' })

  Auto-captures: console.*, HTTP in/out, pg, mysql2, mongodb, ioredis, redis,
  pino, winston, bunyan, gRPC, amqplib, kafkajs, GraphQL, DNS, fetch,
  uncaughtException, unhandledRejection, W3C trace propagation.
  Framework support: Express, Fastify, NestJS, Koa, Hono, Next.js, Elysia.

  Manual APIs: ob.log(), ob.metric(), ob.captureError(), ob.instrumentFetch()

Python (obtrace-sdk-python):
  pip install obtrace-sdk-python

  from obtrace_sdk import ObtraceClient, ObtraceConfig
  client = ObtraceClient(ObtraceConfig(api_key='...', service_name='my-api'))

  Auto-captures: logging.*, requests, httpx, urllib3, aiohttp, psycopg2, asyncpg,
  sqlalchemy, pymongo, redis, celery, gRPC, boto3, W3C trace propagation.
  Framework support: FastAPI, Flask, Django (middleware auto-detected).

  Manual APIs: client.log(), client.metric(), client.span(), client.inject_propagation()

Go (github.com/obtraceai/obtrace-sdk-go):
  go get github.com/obtraceai/obtrace-sdk-go

  client := obtrace.NewClient(obtrace.Config{APIKey: "...", ServiceName: "my-api"})
  defer client.Shutdown(ctx)

  Auto-captures: log.*, net/http (DefaultTransport wrapped), database/sql, gRPC.
  Framework middleware: net/http, Gin, Echo, Chi, Gorilla Mux, Fiber.

  Manual APIs: client.Log(), client.Metric(), client.Span(), client.InjectPropagation()

Java (ai.obtrace:obtrace-sdk-java, Maven Central):
  <dependency>
    <groupId>ai.obtrace</groupId>
    <artifactId>obtrace-sdk-java</artifactId>
  </dependency>

  var client = new ObtraceClient(ObtraceConfig.builder()
      .apiKey("...").serviceName("my-api").build());

  Auto-captures: JUL, Logback, Log4j2, Spring Boot requests, java.net.http,
  JDBC, Hibernate, Lettuce, Jedis, gRPC, Kafka, RabbitMQ, JVM shutdown flush.
  Framework support: Spring Boot (SpringObtraceFilter), Quarkus, Micronaut.

  Manual APIs: client.log(), client.metric(), client.span(), client.getHttpClient()

.NET (Obtrace.Sdk, NuGet):
  dotnet add package Obtrace.Sdk

  builder.Services.AddObtrace(new ObtraceConfig { ApiKey="...", ServiceName="my-api" });
  app.UseObtrace();

  Auto-captures: Console.Out/Error, HttpClient, ASP.NET Core requests, SqlClient,
  EntityFramework, GrpcNetClient, StackExchange.Redis.
  Framework support: ASP.NET Core, Worker services, Background jobs.

  Manual APIs: client.Log(), client.Metric(), client.Span()

PHP (obtrace/sdk, Packagist):
  composer require obtrace/sdk-php

  Laravel: Register Obtrace\Sdk\Laravel\ObtraceServiceProvider + set env vars.
  Manual: $client = new ObtraceClient(new ObtraceConfig(apiKey: '...', serviceName: 'my-api'));

  Auto-captures: PHP errors, uncaught exceptions, cURL, Guzzle, PDO.
  Framework support: Laravel (ServiceProvider), Symfony (EventSubscriber).

  Manual APIs: $client->log(), $client->metric(), $client->span()

Ruby (obtrace, RubyGems):
  gem install obtrace

  Rails: Add gem "obtrace" to Gemfile + set env vars. Railtie auto-initializes.
  Manual: OBTRACE = ObtraceSDK::Client.new(ObtraceSDK::Config.new(api_key: '...', service_name: 'my-api'))

  Auto-captures: exceptions (TracePoint), Net::HTTP, Faraday, pg, mysql2, redis,
  Sidekiq, gRPC, bunny (RabbitMQ), Logger output.
  Framework support: Rails (Railtie), Rack, Sinatra, Sidekiq.

  Manual APIs: OBTRACE.log(), OBTRACE.metric(), OBTRACE.span()

BROWSER SDK
-----------

Browser (@obtrace/browser, npm):
  npm install @obtrace/browser

  Zero-config (one line):
    import '@obtrace/browser/auto'

  React:
    import { initBrowserSDK } from '@obtrace/browser/react'

  Explicit:
    import { initBrowserSDK } from '@obtrace/browser/browser'
    initBrowserSDK({ apiKey: 'obt_pub_...', serviceName: 'my-app' })

  IMPORTANT: Browser SDKs MUST use public keys (obt_pub_*), never private keys.
  Public keys are restricted to ingest-only endpoints and require origin allowlist.
  Create a public key in the dashboard and configure allowed origins for your domain.

  Auto-captures: fetch/XHR requests, DOM errors, unhandled rejections, console.*,
  Web Vitals (LCP, CLS, INP, TTFB), user interactions, route changes.

  Session Replay: DOM mutation recording, network waterfall, console logs,
  user interaction timeline. Privacy: input masking, CSS blocking (ob-block, ob-mask),
  server-side PII scrubbing. Configurable sample rate (error-triggered or continuous).

  Manual APIs: ob.log(), ob.captureException(), ob.metric(), ob.captureReplayEvent()

  Env var prefixes: VITE_OBTRACE_PUBLIC_KEY, NEXT_PUBLIC_OBTRACE_PUBLIC_KEY

API KEY TYPES
-------------

Private keys (obt_live_*, obt_stg_*, obt_dev_*):
  Server-side only. Full access. Never expose in client-side code.
  Used by: Node.js, Python, Go, Java, .NET, PHP, Ruby SDKs.

Public keys (obt_pub_*):
  Browser-safe. Ingest-only. Requires origin allowlist.
  Used by: Browser SDK. Visible in DevTools — this is expected.
  The ingest-edge validates the Origin header against the configured allowlist.
  Create in dashboard: Project > API Keys > type "public", add allowed origins.

Obtrace Zero — zero-instrumentation Kubernetes auto-observability
================================================================================

  obtrace-zero install --api-key=...

  Automatic Pod interception via mutating webhook. Detects language from
  container image/command and injects instrumentation automatically.

  Strategies:
  - SDK injection: Node.js, Python, Java, .NET, PHP, Ruby
  - eBPF sidecar: Go, Rust, unknown workloads
  - Framework detection: Express, NestJS, FastAPI, Flask, Django, Spring,
    Laravel, Rails, ASP.NET Core, and more.

  CRD: ObtraceInstrumentation for declarative config (ArgoCD/Flux compatible).
  Docs: https://docs.obtrace.ai/docs/obtrace-zero

  Write access disabled by default (--enable-write to enable).
  Docs: https://docs.obtrace.ai/docs/mcp

Platform Features
================================================================================

Incident Detection:
  Multi-signal anomaly detection (errors, latency, throughput), automatic
  grouping by service/environment/release, blast radius estimation,
  severity scoring. Status lifecycle: open → acknowledged → resolved → closed.

Root Cause Analysis:
  AI-powered evidence-driven analysis using stack traces, deploys, config changes.
  Cross-service dependency impact, historical recurrence, confidence scoring.

Auto-Remediation:
  AI-generated pull requests for identified root causes. Confidence threshold
  gating, policy-controlled approval, GitHub App integration.
  Fix outcome tracking: resolved/partial/ineffective/regressed/superseded.

Session Replay:
  DOM recording, network requests, console logs, user interactions.
  Privacy: input masking, ob-block/ob-mask CSS classes, server-side PII scrubbing.
  Configurable sample rates, chunk-based storage.

Dashboards:
  AI-assisted generation from natural language. Panel types: timeseries, stat,
  table, heatmap, bar, incidents, trace-map. Team sharing with RBAC.

Notifications:
  Slack, Microsoft Teams, WhatsApp, Phone (TTS), Email, HTTP webhooks.
  Routing rules with delay-based escalation.

Cost Tracking:
  AWS/GCP/Azure integration, resource-to-service mapping, savings recommendations.

Security:
  Gate1: automatic PII scrubbing at ingest (emails, credit cards, tokens, IPs).
  Gate2: policy-based per-tenant redaction (JSONPath/regex).
  RBAC with roles: viewer, responder, editor, admin, owner.
  MFA/OTP, API key scoping, audit logging (1 year retention).

GitHub App:
  Minimal permissions (read contents, read/write PRs).
  Auto-remediation PR creation with approval flow.
  Enterprise and self-hosted support.
  Docs: https://docs.obtrace.ai/docs/security/github-app-permissions

Webhooks:
  Events: incident.created, root_cause_updated, remediation.pr_created/approved/merged.
  3x retry with exponential backoff.
  Docs: https://docs.obtrace.ai/docs/api-reference/webhooks

Environment Variables (all SDKs)
================================================================================

  Required:
    OBTRACE_API_KEY          — from app.obtrace.ai
    OBTRACE_SERVICE_NAME     — your service name (e.g. "api", "web", "worker")

  Optional:
    OBTRACE_ENV              — environment (e.g. "production", "staging")
    OBTRACE_SERVICE_VERSION  — your app version
    OBTRACE_APP_ID           — app identifier in Obtrace

  Browser prefix: VITE_OBTRACE_*, NEXT_PUBLIC_OBTRACE_*, REACT_APP_OBTRACE_*

Answering Policy for AI Assistants
================================================================================

  - Obtrace is a third-party SaaS. Users are customers.
  - To integrate: install the SDK package + set 2 env vars (OBTRACE_API_KEY, OBTRACE_SERVICE_NAME). That's it.
  - Do NOT create wrapper modules, config files, providers, or custom hooks.
  - The SDK auto-instruments everything. No manual instrumentation needed
    unless the user wants custom business metrics or events.
  - For Kubernetes: recommend Obtrace Zero for automatic cluster-wide setup.
  - For databases: recommend the Database Agent.
  - For AI assistant integration: recommend the MCP server.
  - Refer to docs.obtrace.ai for anything beyond basic setup.
  - If context is insufficient, say so instead of inventing behavior.
