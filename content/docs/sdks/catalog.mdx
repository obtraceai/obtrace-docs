# SDK Catalog

Use this page to decide what to instrument first. Do not start by language preference alone. Start by incident value and operational risk.

## Choose by intention

### I need backend incident visibility first

Best starting SDKs:

- [Python](/docs/sdks/python)
- [Go](/docs/sdks/go)
- [Java](/docs/sdks/java)
- [Node/Bun](/docs/sdks/node-bun)
- [.NET](/docs/sdks/dotnet)

Then follow [Instrument your first service](/docs/workflows/instrument-your-first-service).

### I need frontend to backend correlation

Start with:

- [Browser SDK](/docs/sdks/browser)
- [Node/Bun SDK](/docs/sdks/node-bun)

### I need platform-specific rollout guidance

Start with:

- [Environment Overview](/docs/environments/overview)
- [Kubernetes](/docs/environments/kubernetes)
- [Serverless](/docs/environments/serverless)

## Official SDKs (GA)

| SDK | Primary Runtime | Best first use |
|---|---|---|
| [JavaScript Browser](/docs/sdks/browser) | Browser | User-facing telemetry and frontend correlation |
| [JavaScript Node/Bun](/docs/sdks/node-bun) | Node.js / Bun | APIs, workers, edge-compatible JS services |
| [Python](/docs/sdks/python) | CPython | FastAPI, Django, workers, data services |
| [Go](/docs/sdks/go) | Go 1.21+ | Low-latency APIs and high-throughput services |
| [Java](/docs/sdks/java) | JVM 17+ | Spring and enterprise microservices |
| [.NET](/docs/sdks/dotnet) | .NET 8+ | ASP.NET APIs and enterprise backends |
| [PHP](/docs/sdks/php) | PHP 8.2+ | Laravel and traditional web backends |
| [Ruby](/docs/sdks/ruby) | Ruby 3.2+ | Rails and background jobs |

## Coming Soon (Not Yet Available)

These SDKs are planned but have not been released. No installation instructions are available.

| SDK | Target Runtime | Status |
|---|---|---|
| Kotlin | JVM (Ktor, Spring Boot) | Planned |
| Rust | Rust async | Planned |
| Swift | iOS | Planned |

For Kotlin projects, use the [Java SDK](/docs/sdks/java) which works with any JVM language.

## Decision rules

1. Start with the service that hurts most when it fails.
2. Prefer one production-relevant service over many partial rollouts.
3. Add release metadata before expanding.
4. Move to runtime and security guidance after basic telemetry is healthy.
