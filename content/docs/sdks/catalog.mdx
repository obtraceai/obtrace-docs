# SDK Catalog

Use this page to decide what to instrument first. Do not start by language preference alone. Start by incident value and operational risk.

## Choose by intention

### I need backend incident visibility first

Best starting SDKs:

- [Python](/docs/sdks/python)
- [Go](/docs/sdks/go)
- [Java](/docs/sdks/java)
- [Node/Bun](/docs/sdks/node-bun)
- [.NET](/docs/sdks/dotnet)

Then follow [Instrument your first service](/docs/workflows/instrument-your-first-service).

### I need frontend to backend correlation

Start with:

- [Browser SDK](/docs/sdks/browser)
- [Node/Bun SDK](/docs/sdks/node-bun)

### I need platform-specific rollout guidance

Start with:

- [Environment Overview](/docs/environments/overview)
- [Kubernetes](/docs/environments/kubernetes)
- [Serverless](/docs/environments/serverless)

## Official SDKs

| SDK | Status | Primary Runtime | Best first use |
|---|---|---|---|
| JavaScript Browser | GA | Browser | User-facing telemetry and frontend correlation |
| JavaScript Node/Bun | GA | Node.js / Bun | APIs, workers, edge-compatible JS services |
| Python | GA | CPython | FastAPI, Django, workers, data services |
| Go | GA | Go 1.21+ | Low-latency APIs and high-throughput services |
| Java | GA | JVM 17+ | Spring and enterprise microservices |
| .NET | GA | .NET 8+ | ASP.NET APIs and enterprise backends |
| PHP | GA | PHP 8.2+ | Laravel and traditional web backends |
| Ruby | GA | Ruby 3.2+ | Rails and background jobs |

## Decision rules

1. Start with the service that hurts most when it fails.
2. Prefer one production-relevant service over many partial rollouts.
3. Add release metadata before expanding.
4. Move to runtime and security guidance after basic telemetry is healthy.
