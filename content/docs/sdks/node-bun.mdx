## Installation

```bash
npm install @obtrace/sdk-js
```

## Setup

One call. Three fields. Everything else is automatic.

```ts title="src/obtrace.ts"
import { initNodeSDK } from "@obtrace/sdk-js/node";

initNodeSDK({
  apiKey: process.env.OBTRACE_API_KEY!,
  ingestBaseUrl: process.env.OBTRACE_INGEST_URL!,
  serviceName: "payments-api",
});
```

Import this file early in your application entry point (e.g. top of `src/index.ts` or `src/app.ts`). That's it. No middleware, no wrappers, no extra code.

## What's Captured Automatically

After `initNodeSDK()`, the SDK instruments your application at runtime. You don't need to write any code for any of this:

| What | How | Example in Obtrace UI |
|------|-----|----------------------|
| **All console output** | `console.log`, `console.warn`, `console.error` etc. are intercepted and sent as structured logs | `info: "Server started on port 3000"` |
| **Every inbound HTTP request** | Node's `http.createServer` is patched — works with Express, Fastify, Hono, NestJS, Koa, or any framework | Span: `http.request GET /api/orders` with status, duration, trace ID |
| **Every outbound fetch call** | `globalThis.fetch` is replaced with an instrumented version | Span: `server.fetch POST https://stripe.com/v1/charges` |
| **Uncaught exceptions** | `process.on("uncaughtException")` | Log: `fatal: TypeError: Cannot read property...` |
| **Unhandled promise rejections** | `process.on("unhandledRejection")` | Log: `error: unhandledRejection: ...` |
| **Trace propagation** | W3C `traceparent` header injected on outbound, read on inbound | Correlated traces across services |

### What about Express middleware?

You **don't need it**. The SDK patches `http.Server` at the Node level, so every HTTP framework that uses Node's `http` module (all of them) gets instrumented automatically.

The framework-specific middleware (`expressObtraceMiddleware`, `fastifyObtraceHook`, etc.) still exist if you want route-level granularity, but they are **optional** — the default auto-instrumentation already captures method, path, status, and duration for every request.

## Optional: Custom Telemetry

The automatic instrumentation covers infrastructure telemetry. For **business-specific** events, use the SDK methods directly.

`initNodeSDK` returns an object you can use:

```ts title="src/obtrace.ts"
export const ob = initNodeSDK({
  apiKey: process.env.OBTRACE_API_KEY!,
  ingestBaseUrl: process.env.OBTRACE_INGEST_URL!,
  serviceName: "payments-api",
});
```

### Business Metrics

Track KPIs that the auto-instrumentation can't know about:

```ts title="src/routes/checkout.ts"
import { ob } from "../obtrace";

const start = Date.now();
await processCheckout(cart);
ob.metric("checkout.duration_ms", Date.now() - start, "ms");
ob.metric("revenue.amount", order.total, "usd");
```

### Structured Business Logs

`console.log` is captured automatically, but for events you want to query and alert on with specific attributes:

```ts
ob.log("info", "payment.success", {
  attrs: { order_id: orderId, amount, provider: "stripe" },
});
```

### Error Capture

Unhandled errors are captured automatically. For handled errors you still want to track:

```ts
try {
  await db.query("INSERT INTO orders ...");
} catch (err) {
  ob.captureError(err, { attrs: { table: "orders" } });
}
```

## Configuration Reference

| Option | Type | Required | Default | Description |
|--------|------|----------|---------|-------------|
| `apiKey` | `string` | Yes | - | Your Obtrace API key |
| `ingestBaseUrl` | `string` | Yes | - | Obtrace ingest endpoint URL |
| `serviceName` | `string` | Yes | - | Identifies this service in Obtrace |
| `tenantId` | `string` | No | - | Tenant ID (auto-resolved from API key) |
| `projectId` | `string` | No | - | Project ID (auto-resolved from API key) |
| `appId` | `string` | No | - | App ID within a project |
| `env` | `string` | No | - | Environment (production, staging, etc.) |
| `serviceVersion` | `string` | No | - | Deployment version |
| `debug` | `boolean` | No | `false` | Log SDK internals to console |
| `flushIntervalMs` | `number` | No | `2000` | Queue flush interval |
| `maxQueueSize` | `number` | No | `1000` | Max queued items before dropping oldest |
| `requestTimeoutMs` | `number` | No | `5000` | OTLP request timeout |
| `defaultHeaders` | `Record<string, string>` | No | `{}` | Extra headers on OTLP requests |
| `validateSemanticMetrics` | `boolean` | No | `false` | Warn on non-canonical metric names |

## Shutdown

Call `shutdown()` during graceful shutdown to flush buffered telemetry:

```ts
process.on("SIGTERM", async () => {
  await ob.shutdown();
  process.exit(0);
});
```

## Validation

After deploying:

- [ ] Open Obtrace UI — logs should appear under your `serviceName`
- [ ] Make any HTTP request to your server — a span with method, path, status, and duration should appear
- [ ] Call any external API with `fetch()` — an outbound span should appear
- [ ] Add a `console.error("test")` — should appear as an error log
- [ ] Trigger an unhandled exception in test — a `fatal` log should appear
