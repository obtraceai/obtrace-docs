# Catálogo de SDKs

Use esta página para decidir o que instrumentar primeiro. Não comece apenas pela linguagem favorita. Comece pelo valor do incidente e pelo risco operacional.

## SDKs oficiais

| SDK | Status | Runtime principal | Melhor primeiro uso |
|---|---|---|---|
| JavaScript Browser | GA | Browser | Telemetria de UX e correlação frontend/backend |
| JavaScript Node/Bun | GA | Node.js / Bun | APIs, workers e serviços JS |
| Python | GA | CPython | FastAPI, Django, workers e serviços de dados |
| Go | GA | Go 1.21+ | APIs de baixa latência e serviços de alto throughput |
| Java | GA | JVM 17+ | Spring e microsserviços enterprise |
| .NET | GA | .NET 8+ | APIs ASP.NET e backends enterprise |
| PHP | GA | PHP 8.2+ | Laravel e web backends tradicionais |
| Ruby | GA | Ruby 3.2+ | Rails e jobs de background |

## Regras de decisão

1. Comece pelo serviço que mais dói quando falha.
2. Prefira um serviço relevante em produção a muitos rollouts parciais.
3. Adicione metadata de release antes de expandir.
4. So depois avance para ambiente e segurança.
