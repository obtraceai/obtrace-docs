## SDKs oficiais

| SDK | Status | Runtime principal | Melhor primeiro uso |
|---|---|---|---|
| JavaScript Browser | GA | Browser | Telemetria de UX e correlacao frontend/backend |
| JavaScript Node/Bun | GA | Node.js / Bun | APIs, workers e servicos JS |
| Python | GA | CPython | FastAPI, Django, workers e servicos de dados |
| Go | GA | Go 1.21+ | APIs de baixa latencia e servicos de alto throughput |
| Java | GA | JVM 17+ | Spring e microservicos enterprise |
| .NET | GA | .NET 8+ | APIs ASP.NET e backends enterprise |
| PHP | GA | PHP 8.2+ | Laravel e web backends tradicionais |
| Ruby | GA | Ruby 3.2+ | Rails e jobs de background |

## Regras de decisao

1. Comece pelo servico que mais dói quando falha.
2. Prefira um servico relevante em producao a muitos rollouts parciais.
3. Adicione metadata de release antes de expandir.
4. So depois avance para ambiente e seguranca.
