## Guia de Seleção

Priorize por:

1. Criticidade do serviço.
2. Volume de requisições.
3. Prontidão do time para suporte.
4. Restrições do runtime (cold start, memória, edge limits).

## Convenções Compartilhadas entre SDKs

1. Modelo de autenticação consistente.
2. Primitivas centrais alinhadas (log/trace/error + flush/shutdown).
3. Retry/fila variam por runtime, mas são documentados.
4. Taxonomia de troubleshooting compartilhada.

## Padrão de Rollout por Runtime

- Comece com um serviço por linguagem.
- Valide gates de qualidade de dados.
- Expanda por topologia (API síncrona -> workers -> edge/frontend).
- Anexe metadados de release e integração de runtime antes de escalar.

## Definição de Pronto (Por SDK)

- Instrumentação aplicada e revisada.
- Telemetria visível com tags estáveis.
- Correlação erro/trace validada em simulação de incidente.
- Runbook de rotação de chave e falha de transporte documentado.
