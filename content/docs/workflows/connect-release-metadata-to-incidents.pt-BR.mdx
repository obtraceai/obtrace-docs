# Conectar Metadata de Release aos Incidentes

Use este fluxo quando o time já consegue ver telemetria, mas ainda perde tempo respondendo qual release introduziu o problema.

## Objetivo

Ao final, todo incidente deve ser rastreável para uma janela de release, faixa de commits e contexto de deploy.

## Passo 1: Defina os campos mínimos

Propague no mínimo:

- commit SHA
- build id
- horario do deploy
- ambiente
- versão do serviço

## Passo 2: Adicione a integração de CI/CD

Comece com [Integração GitHub Actions](/pt-BR/docs/integrations/github-actions).

## Passo 3: Verifique que a telemetria carrega o contexto

Resultado esperado:

- traces filtraveis por versão
- timeline do incidente mostrando proximidade com deploy
- regressao comparavel ao ultimo release saudável

## Definição de pronto

- Incidentes filtraveis por janela de release
- Comparação entre release quebrado e release saudável
- RCA não mais separada do histórico de deploy
