# Habilite Remediation PRs com Segurança

Use este fluxo quando a telemetria já estiver saudável e você quiser que o Obtrace avance do diagnóstico para mudanças propostas de código.

## Objetivo

Ao final, acesso ao repositório, política de aprovação e regras de confiança devem estar explícitos e seguros.

## Passo 1: Confirme a base de sinais

Não habilite remediation primeiro. Confirme:

- Telemetria estável
- Metadata de release confiável
- Evidência de causa raiz utilizável

## Passo 2: Revise o modelo de decisão

- [Como a IA decide abrir um PR](/pt-BR/docs/concepts/how-ai-decides-to-open-a-pr)
- [Como funciona a análise de causa raiz](/pt-BR/docs/concepts/how-root-cause-analysis-works)

## Passo 3: Restrinja permissões do repositório

- [Permissões do GitHub App](/pt-BR/docs/security/github-app-permissions)
- [Modelo de acesso ao repositório](/pt-BR/docs/security/repository-access-model)

## Passo 4: Defina política de aprovação

- [Fluxo de aprovação de PR](/pt-BR/docs/security/pr-approval-flow)

## Passo 5: Teste um caminho de remediation de baixo risco

Comece com casos estreitos:

- typo de configuração
- binding ausente de env var
- null guard conhecido
- ajuste limitado de recurso

## Definição de pronto

- O acesso ao repositório está intencionalmente restrito
- A política de aprovação está documentada
- Pelo menos um caminho de remediation de baixo risco foi validado
