# Fazer Rollout do Obtrace em Kubernetes

Use este fluxo quando seus principais incidentes em producao acontecem em Kubernetes e voce precisa ligar sintomas de pod a mudancas de aplicacao e release.

## Objetivo

Ao final, incidentes de Kubernetes devem ser diagnosticaveis por um caminho unico que conecta pods, deploys, traces e contexto de repositorio.

## Passo 1: Comece por um deployment critico

Escolha um deployment com custo real de incidente. Nao comece pelo cluster inteiro.

## Passo 2: Instrumente a aplicacao primeiro

Complete [Instrumente seu primeiro servico](/pt-BR/docs/workflows/instrument-your-first-service).

## Passo 3: Anexe identidade de Kubernetes

Capture:

- cluster
- namespace
- deployment
- pod
- container

## Passo 4: Anexe metadata de rollout

Todo deploy deve expor:

- image tag
- commit SHA
- horario do deploy
- ambiente

## Passo 5: Valide modos comuns de falha

Confirme que o setup explica:

- CrashLoopBackOff
- ImagePullBackOff
- OOMKilled
- falhas de readiness probe

## Definicao de pronto

- Um deployment Kubernetes totalmente diagnosticavel
- Falhas de pod ligadas a metadata de deploy
- O time consegue sair do sintoma de restart para uma causa provavel sem navegacao cega
