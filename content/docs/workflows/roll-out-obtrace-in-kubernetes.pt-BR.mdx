# Fazer Rollout do Obtrace em Kubernetes

Use este fluxo quando seus principais incidentes em produção acontecem em Kubernetes e você precisa ligar sintomas de pod a mudanças de aplicação e release.

## Objetivo

Ao final, incidentes de Kubernetes devem ser diagnosticáveis por um caminho único que conecta pods, deploys, traces e contexto de repositório.

## Passo 1: Comece por um deployment critico

Escolha um deployment com custo real de incidente. Não comece pelo cluster inteiro.

## Passo 2: Instrumente a aplicação primeiro

Complete [Instrumente seu primeiro serviço](/pt-BR/docs/workflows/instrument-your-first-service).

## Passo 3: Anexe identidade de Kubernetes

Capture:

- cluster
- namespace
- deployment
- pod
- container

## Passo 4: Anexe metadata de rollout

Todo deploy deve expor:

- image tag
- commit SHA
- horario do deploy
- ambiente

## Passo 5: Valide modos comuns de falha

Confirme que a configuração explica:

- CrashLoopBackOff
- ImagePullBackOff
- OOMKilled
- falhas de readiness probe

## Definição de pronto

- Um deployment Kubernetes totalmente diagnosticavel
- Falhas de pod ligadas a metadata de deploy
- O time consegue sair do sintoma de restart para uma causa provável sem navegação cega
